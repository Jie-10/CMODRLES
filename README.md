# CMODRLES (DRLOS-EMCMO style)

This version is organized for direct use in PlatEMO and follows the coding
style of PlatEMO's `DRLOS-EMCMO` implementation.

## Main differences from the previous package

- Removed the custom `CMODRLES_DQN < handle` agent class.
- DRL variables (`Data`, `model_built`, `count`, `greedy`, `gama`, `net`,
  `Params`) are maintained directly in `CMODRLES.main`, as in `DRLOSEMCMO.m`.
- Reuses the same `Dropout` network utilities used by DRLOS-EMCMO:
  `trainmodel`, `testNet`, `updatemodel`, `trainNet`, `dropout`, `iniA`, and
  `MgaussRandom`.
- Random exploration is used for the first 200 decision rounds.
- The first model is built from 200 replay records.
- Replay storage follows the DRLOS-EMCMO code path with a 500-record cap.
- The network is updated every 50 generations after model construction, using the same update organization as DRLOS-EMCMO.
- `greedy = 0.95` and `gama = 0.9`, following DRLOS-EMCMO.

## CMODRLES-specific RL definitions

State:
1. Mean constraint violation of MP.
2. Mean division-form Tchebycheff set indicator over the reference vectors.

Action:
1. Allocate the auxiliary search-resource block to AP.
2. Allocate the auxiliary search-resource block to DP.

Reward:
The effective survival ratio of offspring generated by the selected auxiliary
population in the new MP. Exact decision-vector duplicates of MP parents or MP
offspring do not receive repeated credit.

## Evolutionary flow per generation

1. MP always generates N offspring.
2. DRL chooses AP or DP, and the selected auxiliary population generates N
   offspring.
3. The two offspring sets are shared.
4. MP applies `EnviromentSelect1` (SPEA2-CDP).
5. AP applies `EnviromentSelect2` (reference-vector diversity + unconstrained
   SPEA2 fitness).
6. DP applies `EnviromentSelect3` (reference-vector diversity + SPEA2-CDP).
7. The selected auxiliary offspring's effective survival contribution to MP is
   stored as the immediate reward.

## Installation

Copy the `CMODRLES` folder into:

`PlatEMO/Algorithms/Multi-objective optimization/CMODRLES`

The `Dropout` subfolder should remain inside the algorithm folder. PlatEMO's
recursive path setup will make these functions available, in the same way as
for `DRLOS-EMCMO`.

Example:

```matlab
platemo('algorithm',@CMODRLES,'problem',@DASCMOP1,'N',100,'D',30,'maxFE',100100);
```

MP is initialized once and AP/DP copy the same initial evaluated solutions,
which preserves the original CMODRLES initialization logic. Each complete
iteration evaluates 2N new offspring (MP + the selected auxiliary task). For
strict FE matching, use `maxFE = N + 2*k*N` for an integer k.

## Dependency note

The DRLOS-EMCMO network implementation uses `mapminmax`, so the MATLAB toolbox
support required by the original PlatEMO implementation is also required here.

With `N = 100`, the first 200 complete decision rounds consume `40100` FEs;
the network is first constructed at the beginning of round 201. Therefore a
very small `maxFE` may intentionally remain in the random-exploration stage.
